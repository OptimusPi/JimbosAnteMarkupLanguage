# motely-wasm 32.2.0

The engine and npm package are back in step at **32.2.0**. This release adds a bot-friendly MCP
server, brings the generated filter types closer to the loader, and ships a new Anaglyph search party.

## New

- **`Motely.Mcp`, a stdio MCP server for bots and agents.** Five snake_case tools:
  `seed_validate`, `seed_search`, `soul_order`, `best_seed` and `analyze_seed`. Each returns short
  text plus structured JSON, reports bad input as an actionable `Error: …`, and is read-only and
  idempotent. Point a client at `dotnet run --project Motely.Mcp`.

- **`Filters/WhimsyDicetrick.yaml`.** An Anaglyph/White search party for Oops! All 6s. Perkeo,
  Showman and at least two Negative skip tags set the scene; the only score is **100 per Oops**.
  Lucky Cat and all side scores are out. A saved seed list is included for convenience, but the
  search party is meant for a wide sweep at whatever seeds per second you like.

- **Bare legendary names in `soulOrder:` are now in the generated schema and TypeScript types.**
  The loader already accepted them; editors and type-checkers did not. Both spellings now load:

  ```yaml
  must:
    - soulOrder: [Perkeo, Canio]
    - soulOrder: [{ legendary: Perkeo }, { legendary: Canio }]
  ```

## Fixed

- **Soul walks and the Jamlyzer tell the same story.** The walk opens every Soul from run start,
  `sources:` no longer narrows which Souls it sees, and `rolls:` counts the run-global Soul-open
  index. The analyzer reports the same shops and Souls a clause reads.

- **CLI search-mode parsing has wider coverage.** `replay`, `seeds`, `keyword`, `random` and bounded
  `sequential` windows share one parser path, with tests for the awkward corners.

## Changed

- **The engine version and the npm version match again.** `MotelyVersion` and
  `Motely.Wasm/package.json` are both `32.2.0`, so the release gate accepts `v32.2.0`.

- **`best_seed` ignores the filter's cutoff** and uses a single thread, so a large seed pile is
  ranked by true score instead of by whatever cutoff the filter happened to carry.

- **Auto cutoff only clamps once a batch is flooding.** It engages at 10% of a batch or 64 matches
  in one batch; below that it behaves like `off`. For a focused pass, `--cutoff max` is the
  setting that trims to improving scores.

## Notes

- `Motely.Wasm/jaml/index.d.ts`, `motely-filter.schema.json` and `vocab.json` are generated by
  `dotnet run --project Motely.CLI -- schema` and are never edited by hand.
- The saved seed list in `WhimsyDicetrick` is just a convenience. Replay counts are not the point
  of the filter; one row scores Oops! All 6s at **100** each, and the fun is finding more seeds.
