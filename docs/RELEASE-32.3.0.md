# motely-wasm 32.3.0

The engine and npm package move to **32.3.0**. This release makes saved seeds easier to sweep,
makes the MCP tools kinder to bots, and restores the WhimsyDicetrick search party.

## New

- **`--seeds all` sweeps every seed saved beside a filter.** Point `--jaml` at a filter and the CLI
  reads each seed saved in that folder once: every filter's `seeds:` block, and the first column of
  every `.csv` and `.txt`. A file that does not load, or an entry that is not a seed, is skipped
  with a warning instead of stopping the run.

  ```sh
  motely --jaml WhimsyDicetrick --seeds all --cutoff off
  ```

- **MCP bare filter names find every filter extension.** `seed_validate`, `seed_search`,
  `best_seed` and `analyze_seed` now try `Filters/<name>.yaml`, `.yml`, `.jaml` and `.json`, so a
  name like `Whimsy_Dicetricks314` finds its `.jaml` file as readily as `longCola` finds its
  `.yaml`. A name or path with no file now says so plainly instead of handing the name to the YAML
  parser.

- **`Filters/WhimsyDicetrick.yaml` carries its saved seed list again.** The Anaglyph/White search
  party for Oops! All 6s is back to its full convenience list: 2,424 saved seeds. The party itself
  is unchanged — 100 per Negative Oops — and the list is only a starting point.

## Fixed

- **`seed_search` explains a filter with nothing to replay.** Asking to replay a filter that has no
  `seeds:` block now returns a clear error naming the modes that can run, instead of a quiet
  "0 matched / 0 searched".

- **`best_seed` says when a filter scores nothing.** A filter with no `should:` clauses gives every
  seed 0, so the tool now says that in its text and returns `scored: false`, rather than presenting
  the first listed seed as a meaningful winner.

- **The sequential mode is described honestly.** Both the MCP and WebMCP tools now say that
  `sequential` sweeps a bounded window of about 3 million seeds from the start of the space, instead
  of calling it an unbounded exhaustive sweep. The behavior is unchanged.

- **`analyze_seed` loads its filter once.** The tool used to reload the filter just to report its
  name; it now keeps the name from the load it already did.

- **WhimsyDicetrick's `Showman` clause loads again.** A stray word had turned the must clause into
  `Showmanjust`, which the loader refused. The search party now loads and replays.

## Changed

- **The engine version and the npm versions match at 32.3.0.** `MotelyVersion`,
  `Motely.Wasm/package.json`, `Motely.Wasm/package-lock.json`, `Motely.Web/package.json` and
  `Motely.Web/package-lock.json` are all `32.3.0`, so the release gate accepts `v32.3.0`.

## Notes

- `Motely.Wasm/jaml/index.d.ts`, `motely-filter.schema.json` and `vocab.json` are generated by
  `dotnet run --project Motely.CLI -- schema` and are never edited by hand.
- Validated locally before release: the Release WASM build ran with `wasm-opt` 130, all 43
  `motely-wasm` tests passed, and the full `Motely.Tests` suite passed (1,454 tests).
